# SPEC-023 Shell 命令执行

状态：**实现中**

## 先说风险

`shell` 工具给 Agent 的是**用户级任意命令执行**——它能读 `~/.ssh`、能删文件、能 `curl` 往外发数据。
这不是靠"过滤几个危险命令"能解决的问题：任何黑名单都会被绕过（`$(...)`、base64、管道、脚本文件）。

所以这份规格的立场是：

> **不给"安全的 shell"，给"被看着的 shell"。**

三条硬规矩：

1. **默认不存在**。不传 `--allow-shell` 时，`shell.run` 根本不注册——模型看不到这个工具，
   连"试一试"的机会都没有。安全默认值不能靠调用方记得配置。
2. **每条命令都要人批**。启用后，每一次调用都走审批门，把**完整命令原文**摆在人类面前，
   由人决定。没有"人类在场就自动放行"这一说（那是对 `agent.spawn` 这类中等风险动作的策略）。
3. **没有人在，就是拒绝**。没有客户端连着 → 直接 `deny`（fail closed）；等人的时间也有上限，
   超时按拒绝处理。

在此之上才是工程约束：超时、输出上限、进程组回收、环境变量白名单、全程留痕。

## 一、执行语义

- 用 `bash -lc <command>` 执行（`-l` 让 PATH 等与人类终端一致，否则 `node`/`npm` 找不到）。
- **独立进程组**（`detached: true`）：超时时 `kill(-pid, SIGKILL)` 回收**整棵进程树**，
  否则 `sleep 100 &` 这类子进程会留下来。
- **cwd = 该对话的工作空间**（`conversations/<id>/workspace`）。这是落脚点，不是边界——
  命令依然能 `cd` 出去，所以它不构成安全保证，只是让"随手写的文件"落在预期的地方。
- **环境变量白名单**：只传 `PATH / HOME / LANG / LC_ALL / TERM / TMPDIR / USER / SHELL`。
  `AGENT_*`（含模型 API Key）**绝不进 shell**——否则 `env` 一条命令就把 Key 打出来了。
- 超时默认 30s（上限 300s）；stdout/stderr 各截断到 64KB（记字节数，超出标记 `truncated`）。

## 二、审计

每一次调用（含被拒绝的）都写事件日志：命令、cwd、退出码、耗时、stdout/stderr 尾部、是否超时。
被拒绝也要留痕——「谁在什么时候想跑什么，人类拒绝了」本身就是审计要的东西。

## 三、审批交互（冻结契约）

| 方向 | 通道 | 形状 |
| --- | --- | --- |
| 宿主 → 客户端 | SSE 事件 `approval` | `{id, action, risk, agent, detail}`（`detail` 是完整命令；另带内核原字段 `agentId`） |
| 客户端 → 宿主 | `POST /api/approval?conversation=<id>` | `{id, decision:'allow_once'\|'allow_always'\|'deny'}` → `{ok:true}` 或 400 |

- `GET /api/state` 增加 `approval` 字段：待批的那一条（没有则 `null`），刷新页面也能看到。
- 客户端渲染成**必须由人点击**的对话框：显示完整命令 + 「允许一次 / 一直允许 / 拒绝」。
  **不允许自动决定**（不能默认选允许，也不能超时自动同意）。
- 没有客户端连接时宿主直接拒绝，不会挂住。

## 验收标准

- **SHELL-001** 默认不注册：不传 `--allow-shell` 时 `shell.run` 不在工具表里（模型看不到），传了才在。
- **SHELL-002** 每次调用都过审批门：策略说 `deny` 时**不执行任何命令**，并返回明确的拒绝错误。
- **SHELL-003** 执行结果形状稳定：`{code, stdout, stderr, durationMs, timedOut, truncated}`；退出码原样透传（非 0 不是异常）。
- **SHELL-004** 超时会杀掉**整棵进程树**（含后台子进程），返回 `timedOut: true`，且不挂住调用方。
- **SHELL-005** 输出有上限：超大 stdout 被截断并标记 `truncated`，字节数如实报告。
- **SHELL-006** 环境变量白名单：`AGENT_API_KEY` 等 `AGENT_*` 变量不出现在子进程环境里（用 `env` 验证）。
- **SHELL-007** cwd 落在该对话的工作空间；工作空间不存在时自动创建。
- **SHELL-008** 每次调用（含被拒绝的）都写事件日志，含命令与结果摘要。
- **SHELL-009** 审批交互：宿主发出 `approval` 事件、人类 `POST /api/approval` 后放行；
  同一 `id` 重复回复只有第一次生效；未知 `id` 返回 400。
- **SHELL-010** **没人在就是拒绝**：无客户端连接时审批请求立刻 `deny`，不挂住；等人超时也按拒绝处理。
- **SHELL-011** 客户端审批对话框：显示完整命令、三个按钮、**必须人工点击**，不允许自动同意；
  待批状态在 `/api/state.approval` 里，刷新页面仍能看到。
