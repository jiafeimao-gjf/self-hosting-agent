# SPEC-024 Markdown 渲染

状态：**已实现**

## 为什么

Agent 说的是 Markdown，而在此之前对话区把它**当纯文本**显示——人类看到的是满屏 `**`、`|`、`###`。
真模型尤其明显：它回答问题时会自觉用标题分段、用列表列点、用表格比数字、用围栏代码给命令。

## 两条硬约束决定了实现形态

1. **零第三方依赖**（整个项目的底线）→ 自己写，只支持真用得上的语法；
2. **Agent 的输出是不可信输入** → **先转义，再产出 HTML**，永远不把源文本里的标签当成标记放出去；
   链接另做协议白名单（`javascript:` / `data:` / `vbscript:` 一律降级成纯文本）。

这两条放在一起，就有了这份实现的形状：**块级标记在原文上识别**（`>`、`#` 一旦先转义就认不出来了），
**但每一段内容都先 `escapeHtml` 再进行内处理**——安全边界仍然是「先转义，再产出 HTML」。

## 支持范围（刻意收窄）

标题、粗体/斜体/删除线、行内代码、围栏代码块、无序/有序列表、引用、分隔线、表格、链接与裸链接。

不支持：嵌套列表、任务列表、图片、脚注、内联 HTML（**这是安全选择**，不是没做完）。

## 谁的内容会被渲染

只有 **Agent 的输出**（`kind: 'agent' | 'thinking'`）。人类消息与系统消息保持纯文本。

这是一条**明确划出来的边界**：人类在输入框里敲的是随手记，不是文档；而且「谁的内容被当成标记解析」
本身就值得说清楚，不该是隐式的。渲染与否还要先过 `looksLikeMarkdown()`，普通句子不白跑一遍解析。

## 流式

流式气泡与正式消息用**同一个渲染器**（不然后者一到就会排版跳变）。
未闭合的语法按字面显示——`**重点` 在第二个 `**` 到来之前就是字面量，这是流式 Markdown 的正常表现。

## 验收标准

- **MD-001** 基础语法：标题 / 粗体 / 斜体 / 删除线 / 行内代码 / 围栏代码块 / 无序与有序列表 / 引用 / 分隔线都能正确产出；渲染是纯函数（同输入同输出），空输入产出空串。
- **MD-002** 安全：源文本里的 HTML **一律转义**（不产出 `script`/`img` 等标签），代码块内容同样转义但原样保留；链接走协议白名单，`javascript:` / `data:` / `vbscript:` 被拒并降级成纯文本；安全链接带 `target="_blank" rel="noopener noreferrer"`。
- **MD-003** 行内代码与代码块里的 Markdown **不被二次解析**（`` `**不是加粗**` `` 保持字面量；围栏里的 `#` 不是标题）。
- **MD-004** 归因：只有 Agent 输出（`agent` / `thinking`）走 Markdown；人类与系统消息保持纯文本；流式气泡与正式消息共用同一个渲染器。
- **MD-005** `looksLikeMarkdown()` 只认真的标记，普通句子（含「两点半再说」这类数字开头）不误判。
- **MD-006** 流式渲染：未闭合的 `**` 按字面显示（不产出残缺的 `<strong>`），闭合后才变成标记；未闭合的围栏也要保留内容。
