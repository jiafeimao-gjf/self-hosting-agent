# SPEC-026 模型全局配置与对话内切换

状态：**实现中**

## 为什么

在此之前"模型配置"只活在**每个对话自己的** `settings.json` 里：

- 想让所有对话都换成某个模型，得**一个个对话去设置页改**；
- 新建对话靠"复制当前活跃对话"起步（SET-014），于是**没有一个地方能一次改全局**；
- 换模型必须绕到设置页去，而设置页是个整页表单——"我就想换一下模型"的成本过高。

这一版把配置分成**两层**：

```
全局默认  <root>/settings.json            一次改，所有「没单独配过」的对话跟着变
   ↑ 被覆盖
对话覆盖  conversations/<id>/settings.json  输入框旁边切一下，只影响这个对话
   ↑ 都没有
内置默认  本机 Ollama qwen3:4b
```

生效顺序：**对话覆盖 > 全局默认 > 内置默认**。

## 关键取舍

**一、新对话不再复制活跃对话的配置，而是跟随全局。**

复制看起来更"贴心"，但它让"全局"形同虚设：改完全局，新建的对话还是老配置（因为它是从别的对话复制来的）。
为了让老用户的行为不退化（"新对话应该用我配过的模型"），全局文件**不存在**时会用当前活跃对话的配置**建立**它，
一次性且幂等——此后全局就是单一事实来源，新对话一律跟随。

**二、"本轮结束后才能切换"由服务端强制，不只是界面禁用。**

改变模型会**回收并重启 Agent**（旧进程用的是旧模型）。在一轮进行中重启 = 把跑到一半的回合腰斩。
界面上禁用选择器是体验，服务端拒绝才是**不变量**——否则任何直接调 API 的路径都能绕过。

**三、切换只影响当前对话。**

"全局"是默认值，不是"立刻广播给所有对话"。改全局只影响**没有覆盖**的对话；
已经单独配过的对话保持自己的选择——否则用户会莫名其妙地被换掉模型。

## 验收标准

- **SET-018** 配置解析顺序：对话有覆盖 → 用覆盖；没有 → 用全局；全局也没有 → 用内置默认。三条路径都要有测试。
- **SET-019** 新对话跟随全局：新建的对话不写自己的配置文件，因此生效的是全局默认；**全局不存在**时用当前活跃对话的配置建立全局（建立后新对话跟随它，且重复调用不再改写）。
- **SET-020** 全局配置可读写：`GET/PUT /api/settings?scope=global`；改全局**不影响已有覆盖的对话**，也不影响它们的运行中配置。
- **SET-021** 本轮进行中拒绝设置变更：`busy` 时 `PUT /api/settings` 返回可读的拒绝原因，**不重启** Agent、不落盘；回合结束后同一请求成功。
- **SET-022** 输入框旁的模型切换器：选项来自模型清单且**当前模型一定在列表里**（端点没返回它也不能丢）；`busy` 时禁用并给出原因；切换只作用于当前对话（`?conversation=` 带对）。
- **SET-023** 切换真的生效：设置变更后 Agent 以新模型重启（`restarted: true`），且历史对话不丢。
