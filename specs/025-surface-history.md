# SPEC-025 界面版本列表与持久化

状态：**已实现**

## 它解决什么

界面面板一直是「画完就只活在内存里」：

- **重启就没了**——重新打开客户端，界面面板是空的，之前 Agent 画的东西一个字都不剩；
- **回滚靠猜**——顶栏那个「回滚」按钮弹一个 `window.prompt`，让人**凭记忆敲版本号**；
  可人类根本不知道 v3 和 v7 分别是什么。

## 一、持久化：不新增一套存储，而是让已有不变量覆盖界面自己

`界面 = f(事件日志)` 是这个项目的核心不变量——**它对界面自己也成立**。所以持久化不是
"再写一份文件"，而是两步：

1. **让界面改动成为事实**：`SurfaceIngest` 在改动成功时写一条 `ui.patch` 事件
   （版本号 / op / scope / spec）。在此之前界面改动**根本没有事件记录**——只有 `agent.frame`
   里的一份原始帧，那是"传输记录"不是"事实记录"。
2. **启动时回放**：`ingest.replay(log.read())` 按序重放 `ui.patch` 与 `surface.rollback`，
   把文档恢复到重启前的样子。回放**不再记事件**（`silent`），否则每重启一次日志就滚一倍。

被拒绝的改动**不记**：它没改任何东西，记了只会让回放重复走一遍拒绝路径。

## 二、回滚也是一次变更

`surface.rollback` 同样写事件。否则"回滚 → 重启 → 回滚失效"——文档会回到回滚**之前**的样子。

`ViewDocument` 的语义不变：**版本号只增不减**，回滚不是时间旅行，而是一笔"内容等于旧版本"的新记录。

## 三、列表：让人看得见、点得动

`GET /api/surface/versions` 返回从新到旧的版本清单：

```json
{"ok":true,"current":7,"versions":[
  {"version":7,"ts":"2026-10-03T13:04:12.000Z","scopes":["surface.main"],"note":"…"},
  {"version":6,"ts":"…","scopes":["surface.main","surface.sidebar"],"note":"…"}
]}
```

版本号与区块数来自文档（`history()`），**时间戳来自事件日志**（文档不记时间）——两边按版本号对齐，
取不到时间就给空串，**不编造**。

界面面板头部有一个版本下拉（`v7 · 21:04:12 · 1 个区块`）+「回到这一版」。
清单最新的排最前：人点的大多是"回到上一版"。原来的「回滚」按钮保留，但改成"选中上一版并恢复"，
不再让人敲版本号。

## 验收标准

- **SURF-014** 界面改动落成事件：`ui.patch` 成功 → 写一条 `ui.patch` 事件（含 version / op / scope / spec）；被拒绝的改动**不写**事件。
- **SURF-015** 启动回放：新建会话时按事件日志回放 `ui.patch` 与 `surface.rollback`，文档版本与各 scope 内容恢复到重启前；回放**不产生新事件**（幂等：重启两次，日志长度不变）。
- **SURF-016** 回滚落成事件：`surface.rollback` 写入事件日志；回滚后重启，文档停在**回滚后**的版本。
- **SURF-017** 版本清单接口：`GET /api/surface/versions` 返回从新到旧的清单（version / ts / scopes / note）与当前版本；时间戳取自事件日志，取不到就空串（不编造）。
- **SURF-019** 重启后的第一帧必须**真的画出来**：页面加载时 iframe 的首次 `load` 可能早于挂监听，此时必须由启动兜底**主动认定 iframe 已就绪**（而不是只补画"待画内容"）——否则后续送来的界面永远卡在待画队列里，面板一片空白且 `srcdoc` 为空；写入之后还要在**加载完成之后**强制重绘一帧（先于加载地隐藏会把这次导航撤掉）。界面面板与浏览器面板同此。真 bug：重启后界面面板空白。
- **SURF-018** 客户端版本列表：下拉里每一版显示 `vN · 时间 · 区块数`，当前版本标注「（当前）」；点「回到这一版」调用 `/api/rollback` 并在成功后刷新清单；回滚失败要有可见错误、不静默。
