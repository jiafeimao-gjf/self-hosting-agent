# SPEC-002 事件日志（Kernel 层）

状态：**已实现** · 对应架构不变量 I3「事件即真相」

整套系统里只有一份真相：**追加写的事件日志**。人类输入、模型输出、工具结果、界面 patch，全部按序落盘；界面状态、Agent 的下一轮上下文、审计视图都是它的投影。

```
界面 = f(事件日志)
```

## 1. 数据模型

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `seq` | integer ≥ 1 | 单调递增，由日志分配，是全局唯一序 |
| `type` | string | 事件类型，如 `loop.step`、`tool.result`、`ui.patch` |
| `ts` | string | ISO8601，**单调不减** |
| 其余 | 任意 | 事件负载（调用方自定义） |

存储形态：`<dir>/events.jsonl`（一行一事件）+ `<dir>/snapshots/<seq>.json`。选 JSONL 而不是数据库，是为了让「追加写、可读、可 diff、可用文本工具排查」这件事在 P0 就成立。

## 2. 语义

- **追加写**：任何状态变化先 `append` 再对外可见；`append` 返回落盘后的完整事件（含 `seq`/`ts`）。
- **水位与快照**：`snapshot(state)` 记录当时的 `seq` 水位；`latestSnapshot()` 取最近一次。回放可以从快照起跳。
- **容错读取**：磁盘上出现损坏行（手改、断电半行）时，`read()` 跳过该行并上报，不得整份日志不可用。
- **回放**：`replay(reducer, initial)` 按 `seq` 升序折叠出状态。任何派生状态（未读消息数、Loop 状态、界面文档）都必须能由回放算出。

## 验收标准

- **LOG-001** `append` 返回的事件带自增 `seq`（从 1 开始）与合法 `ts`，且**立即落盘**：新建实例重新读取能看到同样的事件。
- **LOG-002** 交错调用（await 之间穿插其它 append）不产生重复或跳号的 `seq`。
- **LOG-003** `read()` 按 `seq` 升序返回全部事件；`readFrom(seq)` 返回 `seq ≥ 给定值` 的子集。
- **LOG-004** `snapshot(state)` 落盘且带水位 `seq`；`latestSnapshot()` 返回最近一次的状态与水位的对象。
- **LOG-005** `replay(reducer, initial)` 能从空态或从快照水位起跳，折叠出确定的状态。
- **LOG-006** 损坏行不影响其余事件：`read()` 跳过非法 JSON 行，并通过 `issues()` 上报行号与原因。
- **LOG-007** `ts` 单调不减；`type` 为空字符串或缺失时 `append` 必须拒绝（返回错误而不是写入脏事件）。
- **LOG-008** 事件日志是唯一真相：同一份日志两次 replay 必须得到**深度相等**的状态；且从快照 + 后续事件回放，与从零回放结果一致。
