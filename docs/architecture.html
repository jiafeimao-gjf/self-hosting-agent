00 · 一句话架构

界面是输出，多 Agent 是内核，
一个 Agent 一个子进程。

客户端不是"聊天窗口 + 后端"。它是一台能被 Agent 自己改造的交付终端：界面由 Agent 输出的 View Spec 渲染， 浏览器面板渲染 Agent 写下的 HTML 文件，而 Agent 本身跑在独立子进程里——崩溃、超时、换模型都只影响那一个进程。

核心不变量

界面 = f(事件日志)
界面不是状态，是投影。日志在，界面就能重建——重启、回放、换对话都成立。

核心不变量

上下文 = f(事件日志)
Agent 的记忆不是内存里的数组，而是日志的投影：窗口可裁剪，事实不丢。

核心不变量

权限自上而下收敛
能力在 Kernel，编排在 Runtime，表达在 Surface。Agent 能画界面，但改不了沙箱规则。

01 · 分层

四层：数据自下而上流动，权限自上而下收敛

每一层只依赖它下面那层。越往下，越少改动、越不信任输入。

Surfacesrc/surface · src/client
表达层。View Spec → 校验闸门 → 界面文档 → 沙箱 iframe；Markdown、浏览器面板、文件面板都在这一层。 它决定"能画出什么"，但画不出沙箱外的任何东西。
Bridgesrc/protocol · src/loop
协议层。NDJSON 帧 = 唯一协议真相（帧表派生校验器与方向判定）。Agent Loop 住在这里： 组装上下文 → 模型推理 → 工具分发 → 外发意图 → 检查点。
Runtimesrc/orchestrator · src/runtime
编排层。拉起子进程、路由帧、代办宿主工具、任务板与邮箱、把子进程产出投影成事件。 它决定"谁能做什么"，也是人类与 Agent 相遇的地方。
Kernelsrc/kernel · src/eventlog
内核层。事件日志（唯一事实来源）、工作空间路径守卫、shell 执行器（进程组/白名单/上限）、 审批门。这一层不解释业务，只提供受约束的能力。
↑ 数据自下而上：事实 → 投影 → 界面 权限自上而下：能力收敛在内核 ↓
02 · 内核循环

Agent Loop：一轮 = 五步，外加四道预算闸门

循环住在子进程里（src/loop/loop.ts）。它只跟两样东西打交道：模型端口与工具表。 所有对外的副作用都必须走帧——它没有别的出口。

STEP 1 · assemble
组装上下文
只在步边界消费收件箱；裁剪历史窗口
→
STEP 2 · infer
模型推理
流式增量外发（累积全文，幂等）
→
STEP 3 · dispatch
工具分发
本地执行或请宿主代办；失败不致命
→
STEP 4 · emit
外发界面意图
ui.patch 必须过守卫，被拒也留痕
→
STEP 5 · checkpoint
检查点
记账，然后回到闸门判断是否再来一轮

四道预算闸门（每轮开始前判）

  • maxTurns · 轮数上限
  • maxToolCalls · 工具调用总数上限
  • maxTokens · 累计 token 上限
  • maxWallClockMs · 墙钟时限
  • 命中任一 → budget_exhausted 收工并留痕
  • 人类打断 → interrupted（下一轮起点生效，不硬杀）

为什么子进程

  • 崩溃隔离：模型端口抛错、工具卡死只毁这一个进程，宿主照常服务
  • 换模型＝换进程：设置一改就回收重建，历史由日志投影而来，不丢
  • 强边界：子进程拿不到宿主的对象，只能发帧——"能做"与"被允许做"是两回事
  • 可审计：每个进程有独立日志目录，出问题能单独复现
流式输出：agent.delta 发的是累积全文而不是分片——重复投递不产生副作用。 它是瞬态提示，会被最终的 agent.thinking 取代，因此不进事件日志：一条一条记账只会把日志淹没。
03 · 本页重点

工具调用与返回：两类工具，一条回填链

模型只会说"我要调 workspace.write"。能不能调、谁来调、要不要人类点头，全由宿主决定。 子进程里的 Loop 没有直接能力，它只有一根"请宿主代办"的桥。

类型 A进程内工具（execute: local）

在 Loop 自己的进程里执行：纯计算、读收件箱、写任务板。同步返回，几十毫秒级。

类型 B宿主工具（execute: host）

Loop 干不了的事：拉子进程、改客户端源码、写工作空间、执行 shell。经帧往返宿主，可能阻塞、可能被拒、可能超时。

位置
发生什么
宿主 → 子
human.message 到达 → Loop 在步边界取出，记一条 message.received
子 内部
模型返回 toolCalls: [{ id, name: "workspace.write", args }]，助手消息连同调用一起进上下文（结果才有归属）
子 → 宿主
tool.call 帧发出（{t,agent,seq,ts,id,name,args}），同时记 tool.call 事件； 随后 hostBridge.awaitToolReply(callId, {timeoutMs}) 挂起 —— 会等，但不会永远等
宿主

宿主 → 子
tool.reply 帧回填（{id, ok, result|error}）→ 桥 resolve，Loop 继续
子 内部
结果写进上下文 {role:'tool', text:'[workspace.write] {"path":…}'}，并记 tool.result； 下一轮推理让模型看到它 —— 直到 loop.done

失败不致命

工具不存在 → UNKNOWN_TOOL；宿主超时 → HOST_TOOL_TIMEOUT； 被拒 → 审批被拒绝。这些都作为文本结果回到模型，让它自己决定下一步——而不是把整轮打断。

只声明真的注册了的

宿主工具表是唯一事实：没注册的工具不会出现在给模型的工具清单里。 曾经有个 bug 是把常量表整个声明给子进程，模型于是去调一个不存在的工具，只拿到 UNKNOWN_TOOL。

名字的两个空间

内部工具名允许带点（ui.render），但 OpenAI 的 tools[0].function.name 只接受 ^[a-zA-Z0-9_-]+$。适配器负责外发时净化、回收时映射回来，内部名字不变。

04 · 协议

帧协议与审批门

src/protocol/frames.ts 是唯一的帧表：JSON Schema、校验器、方向判定都由它派生—— 所以"规格说能过"和"实现真能过"不可能各说各话。

帧（节选）

帧方向说明
human.messagein人类说话
peer.messageinAgent 之间：brief / report / note
tool.replyin宿主回填工具结果
approval.reply · interruptin人类批准 / 拒绝 · 人类夺权
tool.callout请求宿主代办
tool.resultout工具结果（已进上下文）
agent.delta · agent.thinkingout流式累积全文（瞬态，不落日志）· 这一步说的话（落日志）
ui.patchout界面意图（必须过守卫）
approval.askout请求人类批准
loop.step / state / done / errorout循环自身的可观察信号

完整 18 种见 src/protocol/frames.ts；信封四件套 t · agent · seq · ts， 严格校验：未知字段与类型不符一律拒收。

审批门：不给"安全的 shell"，给"被看着的 shell"

01

默认不存在。不加 --allow-shell，shell.run 根本不注册——模型看不到这个工具，没有"试一试"的机会。

02

每条都要人批。启用后每次调用都弹对话框，把完整命令原文摆在人面前；「人类在场即放行」这条策略对 shell 无效。

03

没人在就是拒绝。没有客户端连着 → 立即 deny（fail closed），不挂住；等人有上限（默认 10 分钟），超时按拒绝。

04

环境变量白名单。只传 PATH/HOME/LANG/TERM/TMPDIR 等，AGENT_API_KEY 绝不进 shell——否则 env 一条命令就把 Key 打出来了。

05

进程治理。独立进程组 + 超时 kill(-pid)：sleep 100 & 这类后台子进程随整棵树一起回收。

06

审计含拒绝。每次调用都写事件日志：命令、决定、退出码、耗时、是否截断。被拒绝的也留痕。

05 · 事实来源

事件日志即真相

内存里的东西会丢，日志不会。凡是"要能重建"的状态，就必须先成为日志里的一条事实——这条规矩 在开发过程中反复救场：它同时给出了持久化、回放、审计与排障四种能力。

从"传输记录"到"事实记录"

界面的改动原本只存在于 agent.frame 里——那是传输记录，不是事实。 于是"界面 = f(事件日志)"对界面自己不成立：重启必丢。

修法不是新写一套存储，而是让 SurfaceIngest 在改动成功时写一条 ui.patch 事件，启动时按序回放——已有不变量覆盖了新需求。

回放必须幂等

  • 回放不再写事件（silent），否则每重启一次日志滚一倍
  • 回放产出的版本序列与重启前完全一致——回滚也照样执行一次
  • 被拒绝的改动不记：它没改任何东西，记了只会让回放重复走一遍拒绝路径
  • 两套日志各有各的号段：绝不拿一份日志的 seq 去过滤另一份

06 · 客户端

客户端：能被 Agent 自己改造的界面

Agent 可以改客户端的源码（client.write），但必须过自检门禁； 人类永远有 client.revert 一键回滚。界面本身也走"沙箱 + 投影"这套。

三个面板，三个沙箱

<iframe sandbox="allow-scripts">（故意不给 allow-same-origin）。 界面面板画 View Spec；浏览器面板渲染工作空间里的 .html 文件；文件面板按需加载内容。

Markdown 渲染

零依赖自写渲染器，先转义再产出 HTML，链接走协议白名单（javascript: 降级成纯文本）。 只有 Agent 的输出渲染——人类输入保持纯文本，这条边界要明确。

模型配置两层

全局默认（global-settings.json）+ 对话覆盖。输入框旁的切换器本轮结束才可切—— 换模型要重启 Agent，界面禁用是提示，服务端拒绝才是不变量。

自举闭环

Agent 改 .css → 无刷新热替换；改 .js/.html → 只给横幅 + 必须由人点的刷新按钮（不自动刷新，免得打断正在进行的对话）。

审批对话框

SSE approval → 展示完整命令原文与风险等级 → 三个按钮。必须人工点击： 没有默认同意、没有回车同意、没有超时同意，初始焦点在「拒绝」上。

界面版本列表

每一版都有时间戳与区块数，点一下回到那一版。回滚也是一次变更、也写日志—— 否则"回滚 → 重启 → 回滚失效"。

可观察性

  • 事件日志：领域事实（谁要求了什么、成了没有）
  • 诊断日志：排障细节（分级、可回显到终端）
  • 时间线：人类可读的事件摘要
  • Agent 进程表：pid / 存活

失败的处理方式

  • 模型报错 → 记 loop.error，本轮以 error 收工，进程不死
  • 工具报错 → 作为文本回到模型，由它决定下一步
  • 审批超时 → 按拒绝处理，并留痕
  • 沙箱不认流式 → 自动降级为非流式重发

这套架构的代价

  • 帧协议要严格：字段改动必须同步帧表与规格
  • 子进程多一层调试成本（所以有独立日志目录）
  • 投影要盯"最终产物"：属性对了不等于画面出来了
  • 零依赖意味着轮子得自己造（Markdown、SSE 解析、门禁）

本文档由开发过程沉淀：每条不变量背后都有对应的验收判据与测试（npm run check 会同时跑 规格追溯门禁与全部测试）。判据数、测试数随代码一起更新。
